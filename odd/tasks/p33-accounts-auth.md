### Implementation bindings (technical decisions, not additional product features)

- T1 units are disjoint and genuinely independent: A mailbox compatibility updates existing mail and adds a shared mailbox parser; B identity-security primitives/config; C account-mail-outbox envelope/repository/worker. HTTP/domain integration follows after their stable exports are observed.
- Parent owns package/lock, shared protocol constants `apps/api/src/identity-protocol.ts`, feature/roadmap/index and integration wiring. Protocol constants have no secret or behavior; account-token digest is SHA256 of domain +NUL+storedpurpose +NUL+rawcanonicaltoken; session verifier uses a distinct domain. Only constants are shared; no B↔C runtime import dependency.
- A public helper `apps/api/src/mail/mailbox.ts` validates one broad bare mailbox, returns preserved trimmed delivery input (no display-name/list/control/header injection), with lowercase-domain precondition. Existing AccountMailService methods/signature stay stable. Use a maintained parser/validator rather than reinventing RFC grammar; standard wire encoding may be necessary for international domains. Parent researches/pins library. Update old tests only for newly accepted formats and retain existing ASCII/guard/failure/lifecycle behavior. Add real owned-Mailpit cases for quoted and international addresses.
- B exports through `apps/api/src/identity-security/index.ts`: fail-closed identity config from supplied env object, password hash/verify/dummy-check with bounded capacity,32byte opaque verifiers/purpose digest, session cookie/CSRF helpers and raw Unicode/body validation primitives. Read exact contract for names/cookies/keys; no HTTP/DB implementation here. Prefer @node-rs/argon2@2.2.2 (official prebuilt NAPI, no install script), explicit Argon2id19MiB/t2/p1, locally measure rather than reuse upstream benchmark numbers.
- C exports through `apps/api/src/account-mail-outbox/index.ts`: validated keyring config from provided env; seal/open envelope with canonical AAD; transactional enqueue helper accepting an existing Prisma transaction (does not commit independently); owned-type leased runOnce worker with a structural SMTP sender port matching existing sendVerification/sendRecovery. Worker scheduling/lifecycle is later AuthModule wiring, not an extra daemon. Token/user metadata state and digest must agree before send; no network I/O while holding long DB/user transactions. Retry is bounded by token expiry and lease ownership; no exactly-once SMTP claim. Do not depend on B source; use shared protocol constants and existing Prisma models. Fixture/probe data only in isolated state; expose sanitized operational results, never secrets.
- Parallel typechecks must not compile each other's incomplete source or overwrite shared build artifacts. A/B/C each own a narrow `apps/api/tsconfig.p33-<unit>.json` extending the existing config with explicit unit-only include/import closure and unique `.build/p33-<unit>` output. Parent generates unchanged Prisma client before checks if needed; no concurrent root api:build or node_modules mutations. Each unit's exact test script/compiled path is documented in its guide/record; whole-app build is parent seam after all settle.
